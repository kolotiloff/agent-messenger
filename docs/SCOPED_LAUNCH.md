# Запуск только выбранной сессии

В preview.19 запуск новой тестовой сессии Claude доступен из окна: «Агенты» → Claude Code → «Сессии» → «Запустить тестовую сессию». Создать её можно через «Настроить». Кнопка явно разрешает обработку писем только выбранной сессии и возобновляет очередь. Если письма уже поставлены этой сессии, они начнут обрабатываться. Другие адресаты остаются в очереди. Ответы расходуют токены; пустое ожидание не отправляет запросов модели.

Кнопка доступна только для созданной Messenger новой тестовой сессии без владельца. Старые зарегистрированные и рабочие разговоры этим действием не подключаются. Пока в клиенте действует одно разрешение, переключить его на другую сессию нельзя. Повтор подтверждения возвращает тот же результат и не возобновляет последующую паузу. Разрешение не сохраняется после остановки фонового клиента; закрытие одного окна не равно остановке клиента. После попытки защитный резерв может оставаться — кнопка не обходит его.

Для терминала есть ограничение `--only-session АДРЕС` у `serve` и `start` в режиме `--claude-stream`. Оно не разрешает вызовы модели само по себе. Необходим `--allow-model-calls`, а фоновый `start` начинается на паузе.

Клиент выбирает письма только точной зарегистрированной сессии указанного адреса. Другие её псевдонимы относятся к тому же разговору. Письма остальных сессий остаются в очереди, даже если выбранный адрес не существует, его очередь пуста или за ним удерживается защитный резерв. В таком случае нет перехода к следующему агенту. Ошибочный провайдер и незавершённая настройка отклоняются до создания попытки. Адаптер дополнительно проверяет выбранный адрес перед запуском процесса.

`status` возвращает `launch_session`; окно показывает ограничение и не обещает обработку писем других сессий. Обычный запуск `desktop` не включает ни это разрешение, ни модель. Смена области запуска требует штатной остановки клиента и нового явного запуска; она не снимает прежние защитные резервы. Пауза сохраняет живой процесс и блокировку сессии.

Изолированные проверки с тестовым CLI: два последовательных письма одной сессии обработаны одним PID; более старое письмо другой сессии не взято; перезапуск не обходит удерживаемую выбранную сессию. Проверены передача ограничения фоновому процессу и отсутствие автоматического выбора другой очереди. Реальные модели этими тестами не запускаются.

На Mac также пройден весь путь через окно с имитатором CLI: создание, разрешение, два письма, два связанных подтверждённых ответа в одном процессе. Ответы и очередь обновляются автоматически, чтение локальных данных не вызывает модель. При просмотре старой истории прокрутка не сбрасывается; свежая страница загружается при повторном выборе сессии или ручном обновлении. Настоящая модель этой проверкой не вызывалась.
