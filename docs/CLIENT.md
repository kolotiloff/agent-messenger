# Локальный клиент

Сделано 5 ноября 2026 года. Это постоянный локальный клиент на Python 3.9+ из стандартной библиотеки, без дополнительных пакетов. Каталог кода: `src/agent_messenger`. Исследовательский стенд `experiments/session_safety` остаётся отдельным и этим клиентом не заменяется.

Переписывание на Go этим этапом не требуется и не начато. Предварительный выбор Go в [плане](PLAN.md) относится к будущей упаковке, а не к этому клиенту. Окна, сетевого брокера, установщика, LaunchAgent и автозапуска нет.

## Что сделано

Один процесс `serve` владеет очередью и запусками. Второй супервизор не стартует: на каталоге хранилища висит отдельная блокировка ОС (`flock`, на Windows заготовлен `msvcrt.locking`, он здесь не проверялся). Команды и будущее окно подключаются к этому процессу по локальному сокету и сами CLI не запускают. Транзакции SQLite `BEGIN IMMEDIATE` остаются дополнительной защитой от двух резервирований одной сессии.

Хранилище одно на пользователя, а не отдельная база на каждый запуск:

| ОС | Каталог |
|---|---|
| macOS | `~/Library/Application Support/AgentMessenger` |
| Linux | `$XDG_DATA_HOME/agent-messenger` или `~/.local/share/agent-messenger` |
| Windows | `%APPDATA%\AgentMessenger` |

Тесты передают временный `--data-dir` и в эти каталоги не пишут. Каталог создаётся с правами `0700`. Очередь переживает перезапуск процесса.

Ключ сессии: провайдер, канонический путь существующего каталога окружения CLI, точный ID разговора. Почтовое имя — только псевдоним этого ключа. Два псевдонима или два написания одного пути, включая символическую ссылку, не дают второй запуск. Без реального каталога сессия не регистрируется. Продолжение только по точному ID: `--last`, `--continue` и «последняя сессия» отвергаются.

MCP одного исполнения даёт только `read_current` и `reply(text)`. Читать и отвечать можно после подтверждения ID запуска. Повтор того же текста возвращает сохранённую запись. Другой текст с тем же контекстом отвергается. Маршрут задаёт клиент.

Обычный `status`, пауза и пустое ожидание не вызывают модель и не запускают адаптер. Реальные Claude, Codex и Cursor этим набором тестов не запускаются. Их разбор командной строки и событий перенесён из проверочных проб и закрывается при ошибке; включение запуска требует одновременно флага `--allow-model-calls` и `"allow_model_calls": true` в конфигурации хранилища.

В конфигурации зарезервирована граница брокера: `broker.mode` сейчас может быть только `local_only`. Режимы подключения и локального сервера отвергаются до запуска. Клиент не открывает сетевой брокер.

## Команды

Глобальный флаг `--data-dir` стоит перед командой. Без него используется каталог выше.

| Команда | Очередь | Активный процесс | MCP текущей попытки |
|---|---|---|---|
| `pause` | остаётся | не получает сигнал и не помечается выполненным; новые захваты не делаются | остаётся действительным, пока попытка `running` |
| `unpause` | снова можно захватывать свободные сессии | не меняется | не меняется; удержание `uncertain` / `failed` не снимается |
| `stop-current` | остальные письма остаются | записанной группе процессов может быть послан сигнал; сигнал не доказывает остановку дерева и не отменяет уже сделанное | право чтения и ответа снимается сразу; состояние `uncertain`; автоматического повтора нет; слот занят |
| `shutdown` | остаётся на диске | не убивается и не помечается успешным | этой командой не отзывается. Следующий `serve` не усыновляет чужой процесс: попытку, которую он сам не запускал, переводит в `uncertain`, отзывает MCP и не запускает сессию снова |
| `enqueue` | добавляет письмо через работающий клиент | не запускает модель сам по себе | не меняет чужой контекст. Тот же ID и то же содержимое не создают вторую запись; тот же ID с другим содержимым или маршрутом отвергается |
| `status`, `inspect` | только чтение | не сигнализируется | не вызывается |
| `fail-closed` | текущее письмо закрывается без повтора, история сохраняется; другие письма остаются, но сессия не запускается | не объявляется остановленным | уже отозван, если попытка была `uncertain`; слот не отдаётся |
| `accept-verified` | не меняется | не объявляется остановленным | не принимает результат |
| `authorize-attempt` | не создаёт новую попытку | не объявляется остановленным | не создаёт запуск |

`accept-verified` требует текст проверки, который не сводится к самому ответу. Даже с таким текстом команда отказывается: надёжное доказательство, что старое дерево процессов завершилось, не реализовано. `authorize-attempt` требует точную фразу `--acknowledgement actions-may-repeat` и предупреждает, что действия могут повториться, но попытку не создаёт по той же причине. Отсутствие PID, повторное использование PID, записанное время старта, пустая группа процессов и смена boot id доказательством не считаются. Таймера, который снимает блокировку, нет.

Успешное завершение — другой путь, не восстановление. Его записывает только тот супервизор, который сам дождался своего прямого потомка, после нулевого кода выхода, сохранённого ответа и подтверждённого ID. Для реального CLI дополнительно должен пройти разбор событий. Это не проверка «процесса больше нет в таблице».

Запуск пишет pid, группу процессов и, на Linux, время старта из `/proc`. Эти поля лежат в журнале для будущего разбора и сами по себе ничего не открывают.

## Проверено и не проверено

Проверено в этой Linux-среде, без моделей:

```sh
PYTHONPATH=src python3 -m unittest discover -s tests -v
python3 -m unittest discover -s experiments/session_safety -v
```

Ожидание: `tests` — 31 тест, стенд — прежние 19 тестов, оба `OK`. Стенд не запускает `claude_probe.py` и `resume_probe.py`.

Не проверено и не считается сделанным: реальный запуск Claude, Codex или Cursor этим клиентом; `go test` не используется; окно; сеть; автозапуск; Windows и macOS как среда этих тестов. На Windows сигнал группы процессов в этом коде не поддержан и не выдаётся за успех.

Исторические отчёты в `docs/reports/` не переписывались. Ранние «13 тестов» и последующие 15 и 19 — последовательные снимки того дня: [13](reports/2026-11-05-session-safety-mac.md), [Claude](reports/2026-11-05-guarded-claude-mac.md), [Codex/Cursor](reports/2026-11-05-guarded-codex-cursor-mac.md).

## Проверка на Mac

Реальные CLI не входят в обычный unittest. Они тратят токены и остаются отдельным явным шагом. Службу, LaunchAgent и автозапуск не ставить. Рабочие чаты GUI и текущий разговор координатора не использовать. Нужна новая сессия или уже существующая простаивающая тестовая сессия, которая не открыта в другом CLI или GUI. Хранилище одно: канонический каталог macOS выше, а не новая база на каждый запуск. Идентификаторы сессий, `ipc.token`, `queue.sqlite` и журналы `runs/` в git не класть.

Без моделей, из корня репозитория:

```sh
PYTHONPATH=src python3 -m unittest discover -s tests -v
python3 -m unittest discover -s experiments/session_safety -v
PYTHONPATH=src python3 -m agent_messenger serve
```

Во втором терминале, без `--data-dir`, чтобы попасть в тот же канонический каталог:

```sh
PYTHONPATH=src python3 -m agent_messenger status
PYTHONPATH=src python3 -m agent_messenger pause
PYTHONPATH=src python3 -m agent_messenger unpause
PYTHONPATH=src python3 -m agent_messenger shutdown
```

Успех этого шага: оба набора тестов `OK`; `status` показывает `broker_mode` = `local_only`, `broker_started` = false и `model_launches` = 0; второй `serve` при живом первом завершается отказом блокировки и не запускает CLI; `pause` не удаляет очередь; `shutdown` завершает процесс супервизора, каталог хранилища остаётся; повторный `serve` поднимает сохранённую очередь и сам модель не вызывает.

Реальные CLI, только после этого и только на тестовой сессии. Сначала один раз запустить `serve` и остановить его, чтобы появился `config.json`, затем выставить в нём `"allow_model_calls": true` и оставить `"broker": {"mode": "local_only"}`. Дальше снова один супервизор:

```sh
PYTHONPATH=src python3 -m agent_messenger serve --allow-model-calls
```

Регистрация привязывает реальный каталог окружения CLI, не подпись в интерфейсе. Для Claude это обычно разрешённый путь `~/.claude`, если именно этот каталог является хранилищем нужного входа. Для Codex — реальный `CODEX_HOME` или `~/.codex`. Для Cursor адаптер отказывается запускаться, если существует `~/.cursor/mcp.json` или задан `CURSOR_CONFIG_DIR`; отдельный тестовый каталог — другая идентичность окружения, и открытый GUI-чат туда не входит. ID разговора — точный UUID тестовой сессии. Клиент только возобновляет его и не создаёт новый разговор флагом `--session-id`.

```sh
mkdir -p /tmp/agent-messenger-claude-workspace
PYTHONPATH=src python3 -m agent_messenger register-session \
  --provider claude \
  --environment "$HOME/.claude" \
  --conversation-id 'TEST_SESSION_UUID' \
  --alias claude-test \
  --workspace /tmp/agent-messenger-claude-workspace \
  --cli /absolute/path/to/claude
PYTHONPATH=src python3 -m agent_messenger enqueue \
  --message-id m1 --alias claude-test --sender test-coordinator --text 'PAYLOAD-one'
PYTHONPATH=src python3 -m agent_messenger enqueue \
  --message-id m2 --alias claude-test --sender test-coordinator --text 'PAYLOAD-two'
PYTHONPATH=src python3 -m agent_messenger inspect
```

Для Codex и Cursor заменяются `--provider`, `--environment`, `--cli`, `--alias` и при необходимости `--workspace`. Второй псевдоним того же пути и того же ID не должен запустить второй CLI.

Успех модельного шага: два письма одной и той же тестовой сессии; ответы ровно `ACK:` и текст письма без пробела; `reply_to` указывает на исходное письмо; второе письмо не начинается, пока первый процесс не завершился под этим супервизором; `model_launches` становится 2; конкурирующий запуск блокируется. `pause` не убивает активный CLI. `stop-current` оставляет `uncertain`, отзывает MCP и не повторяет задание. `shutdown` не помечает выполнение успешным и не убивает CLI; следующий `serve` переводит эту попытку в `uncertain` и не запускает её снова. Этот успех не доказывает восстановление дерева процессов: `accept-verified` и `authorize-attempt` по-прежнему должны отказывать.
