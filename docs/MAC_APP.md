# Приложение Agent Messenger.app

Первая нативная оболочка для Mac: AppKit, системный WKWebView и встроенный Go-клиент. Отдельный браузер, Python, Node, Go и терминал для обычного открытия не нужны. Выбранное оформление design/v1 сохранено. Это локальный preview, не готовый сетевой релиз.

## Установка и открытие

Распакуйте проверенный `Agent-Messenger-mac.zip` и перенесите `Agent Messenger.app` в пользовательскую папку `~/Applications` («Программы»). Открывайте двойным щелчком или через Spotlight/Dock. Пакет пока имеет ad-hoc подпись: чистое распространение через Gatekeeper, Developer ID и notarization не принято. Обход защит macOS не требуется и не предлагается. Проверено локально на Apple Silicon; минимальная версия оболочки — macOS 15, Intel отдельно не принят.

При открытии оболочка находит прежнюю базу по существующему защитному реестру либо использует обычный пользовательский каталог, когда резервов нет. Несколько разных каталогов, повреждённый реестр или исчезнувшая сохранённая база дают отказ. Резервы не удаляются и не восстанавливаются автоматически. Если работающий клиент использует другой каталог без записанных резервов, выберите его через меню «Файл → Выбрать каталог данных…»; никакого поиска «последней сессии» нет.

Приложение подключается к уже работающему клиенту. Если клиента нет, запускает один фоновый экземпляр, на паузе и без разрешения моделей. Глобальная блокировка защищает и этот путь. Открытие уже работающего клиента не меняет его паузу или ранее выданные разрешения. Собственное окно не вызывает CLI и не авторизуется за пользователя.

Красная кнопка закрывает окно, но приложение остаётся в Dock; «Файл → Открыть окно» или повторное открытие приложения возвращает его. Cmd+Q закрывает оболочку и её локальный HTTP-процесс. Фоновый клиент, очередь и владельцы CLI остаются. Приложение не вызывает shutdown при закрытии. Свой UI-процесс живёт, пока открыт унаследованный канал stdin; при падении оболочки EOF закрывает HTTP-сервер. Автоматического перезапуска моделей нет.

## Границы интерфейса

Встроенный WebView получает только случайный приватный loopback-адрес своего UI-процесса. Он не открывает внешние сайты, новые окна, file URL и произвольные переходы. Хранилище WebView непостоянное; после полного выхода неотправленный текст может исчезнуть. Уже записанные исходящие восстанавливаются из SQLite по прежним правилам. Дополнительные черновики и автоматическое обновление пока не включены.

Существующие функции окна — сообщения, история, карточки, отправка, пауза. Создание/вход CLI, брокер, четыре компьютера, безопасное освобождение старых владельцев и подписанное распространение остаются отдельными этапами.

## Сборка и проверки

Из проверенных исходников на Mac со стабильным Go и Apple Command Line Tools:

```sh
bash scripts/build-mac-app.sh /абсолютный/новый/каталог 0.0.0-preview.3 ПОЛНЫЙ_SHA
python3 scripts/check-desktop.py '/абсолютный/новый/каталог/Agent Messenger.app/Contents/Resources/messenger'
```

Сборщик отказывается перезаписывать существующий app/zip, собирает Go с CGO_ENABLED=0, компилирует Swift, создаёт иконку, подписывает собственный bundle ad-hoc, проверяет подпись, печатает version и создаёт zip с SHA-256. SOURCE_SHA задаётся вызывающим; для выпуска нужна сверка чистого состояния исходников.

Автотест на отдельном HOME проверяет запуск без моделей, подключение двух UI к одному клиенту, EOF/повторное открытие без потери очереди и отсутствие попыток модели. Go-тесты отдельно проверяют выбор каталога, неизменность резервов и отказ от model-флагов. CI собирает bundle и проверяет мост, но не выдаётся за визуальный тест WebView.

На пользовательском Mac окно открыто нативно: доступны история и карточки; закрытие окна и возврат через меню проверены. Полный набор Go с race прошёл. В тестах реальных моделей нет.

Основания оболочки: [NSApplication](https://developer.apple.com/documentation/appkit/nsapplication), [WKWebView](https://developer.apple.com/documentation/webkit/wkwebview). Ядро Messenger остаётся на Go; Swift — только платформенная оболочка macOS.

## Первый приоритет: обновления из окна

Согласовано 6 ноября: приложение проверяет новые версии обычным кодом и показывает ненавязчивый значок «Доступно обновление». Пользователь видит версию и изменения, затем выбирает «Обновить и перезапустить» либо «Позже». Проверка/скачивание не вызывают модель. Автоматическую проверку можно отключить; выпуск без настроенного источника не изображает себя обновляемым.

Перед установкой проверяются источник, подпись пакета, архитектура, минимальная ОС, совместимость локального API и схема данных. Контрольная сумма сама по себе не заменяет доверенную подпись. Загрузка сначала идёт в отдельный временный каталог; обрыв не повреждает установленную версию. Рабочая версия и её данные сохраняются до подтверждения успешного запуска новой.

Оболочка и фоновый клиент могут иметь разные времена жизни. Обновление нельзя превращать в убийство агента, сброс резервов или произвольное понижение схемы SQLite. Если поддерживаемого безопасного перехода нет, скачанный пакет ждёт, а окно объясняет причину и предлагает установить позже. Пауза очереди и пустая группа процессов не доказывают остановку всех потомков.

Источником могут быть GitHub Releases и подписанные метаданные выпуска; отдельный VPS для обновлений не обязателен. Пока репозиторий закрыт, нужен явно разрешённый доступ только на чтение пакетов, с секретом в защищённом хранилище ОС. Токен разработчика или текущего GitHub-коннектора внутрь приложения не встраивается.

Приёмка: новая/та же/более старая версия, неверная подпись, другая архитектура, потеря сети, повреждённый архив, недостаток места, отказ прав, активный CLI-владелец, несовместимый API, сохранение очереди/исходящих и сбой первого старта. Автоматическая установка пока не реализована; сначала нужны версионированные подписанные выпуски и завершение безопасного жизненного цикла клиента.

Приоритет уточнён 6 ноября: сначала обновления, затем остальные продуктовые функции. Для Mac выбран Sparkle как основа; интеграция ещё не реализована. Первая установка сборки с обновлятором выполняется один раз вручную. Критерий готовности — реальный переход между двумя сборками из окна с сохранением данных, а не наличие кнопки. Порядок разделов окна: **Переписка → Очередь → Агенты → Сервер**.
