Состав: один VPS, клиент на Mac, клиент на `win-1`, одна тестовая управляемая сессия Claude, одна тестовая сессия Cursor CLI, локальный MCP и журнал состояний. Нативный Windows — первый кандидат. Два остальных компьютера подключаются после приёмки, без изменения протокола.

Первый рабочий сценарий:

1. Пользователь инициирует сообщение тестовому Claude-координатору. Claude отправляет запрос Cursor через `messenger.send` и завершает ход.
2. Windows-клиент устойчиво принимает письмо, занимает сессию и запускает Cursor по сохранённому ID.
3. Cursor получает простую задачу по тестовому тексту, отвечает через MCP; клиент фиксирует итог и завершение.
4. Mac-клиент принимает ответ. Когда управляемая Claude-сессия свободна, он возобновляет её; Claude подтверждает результат для пользователя и останавливается без нового автоматического поручения.
5. Второй запрос ссылается на информацию из первого обмена. Оба агента продолжают свои прежние сессии после перезапуска фоновых клиентов.

Если сохранить рабочий Claude в открытом интерактивном терминале, доступен другой режим: письмо приходит в inbox, но автоматический запуск этого разговора ждёт передачи владения. Это честное ограничение первого MVP. Работающий координатор проекта не переносится под управление клиента автоматически.

Этапы после согласования:

| Этап | Конкретный результат |
|---|---|
| A. Проверка адаптеров | Записаны версии, ОС, способы входа, команды, реальные ID и события; H1/H2 и разрешения MCP проходят на тестовых сессиях |
| B. Транспорт без моделей | Брокер, локальные очереди, авторизация, адресация, ACK, повторная доставка и блокировки проверены синтетическими сообщениями |
| C. Полный круг | Реальный Claude → Cursor → Claude и повторное продолжение после перезапуска |
| D. Сбои и ожидание | H6–H9, отзыв токена, состояние `uncertain`, журнал результата и остановка при необходимости разрешения |
| E. Универсальность | Codex проходит H3 и заменяет участника с тем же почтовым интерфейсом; смена координатора проходит H12 |
| F. Четыре компьютера | Второй Windows и Linux подключаются как новые узлы; проверяются их профили и автозапуск |

Для приёмки именно минимального Mac↔Windows достаточно A–D. Поддержку трёх поставщиков и четырёх компьютеров считаем подтверждённой только после E–F.

Критерии приёмки A–D: два последовательных обмена с сохранением ID; второе одновременное письмо ожидает; повторная доставка не создаёт нового обращения к модели; offline-письмо приходит после восстановления связи; клиент и брокер можно перезапустить без потери зафиксированных сообщений; неоднозначный сбой не запускает задачу снова; час ожидания не вызывает модель; отзыв ключа работает. Unity-файлы и настройки Plastic не меняются тестами.

Результат MVP — устанавливаемые компоненты, тестовые конфигурации без секретов, инструкция запуска/остановки и отчёт по этим критериям. Большой графический интерфейс, вложения, автоматическая миграция истории, управление Unity и автоматическая обработка рабочего roadmap в объём A–D не входят.
