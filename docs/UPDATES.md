# Обновления приложения на Mac

Первый рабочий канал — **локальные подписанные сборки на этом Mac**. Пакеты пока не скачиваются из GitHub: доступ GitHub-коннектора не передаётся приложению. Это позволяет разработчику подготовить новую сборку на той же машине, а пользователю установить её кнопкой, без ручной замены `.app`.

## Использование

После первой установки приложения с обновлятором новая версия появляется внизу левой панели: «Доступно обновление» и её номер. Нажатие открывает описание изменений и установку через Sparkle. Можно отложить установку. Ручная проверка доступна там же и в меню Agent Messenger → Проверить обновления. Автоматические проверки можно выключить в меню; автоматическая установка без нажатия отключена.

Публикацию в локальный канал приложение замечает через событие файловой системы, без опроса модели. Дополнительно действует периодическая проверка Sparkle. Проверка версии, скачивание, ожидание и установка не вызывают Claude, Codex или Cursor.

## Что именно обновляется

Sparkle заменяет приложение и встроенный интерфейс, затем открывает его снова. **Уже работающий фоновый клиент сохраняется с прежней версией.** Обновление приложения не выдаётся за обновление живого клиента: это явно указано в описании установки. Существующие агенты, пауза, разрешение моделей, база и защитные резервы не изменяются.

Новые фоновые процессы, запущенные оболочкой, используют отдельную копию бинарника в `runtimes/<sha256>/messenger` под пользовательским каталогом данных. Замена `.app` не меняет этот файл и путь MCP-подпроцессов. Старые версии не удаляются автоматически. Следующий штатный запуск клиента использует новую сборку; принудительного перехода активных сессий нет.

Первый канал принимает только пакеты с совместимым `client_api=1`, текущими ОС и архитектурой, схемой метаданных 1 и macOS не ниже 15. Он не предназначен для миграции SQLite или несовместимой смены протокола. Полная смена фонового клиента, безопасное завершение владельцев и миграции остаются отдельной обязательной частью обновлений. Неотправленный текст поля ввода пока не является сохранённым письмом и может исчезнуть при закрытии окна; уже записанные исходящие и очередь сохраняются.

## Доверие к сборкам

Используется [Sparkle 2.10.1](https://sparkle-project.org/documentation/). Скрипт сборки загружает официальный архив и проверяет зафиксированный SHA-256. Лицензия библиотеки включается в приложение. Публичный Ed25519-ключ находится в `desktop/macos/update-public-key.txt`; приватного ключа нет в репозитории или пакете. Он хранится в Keychain разработчика с отдельным именем `agent-messenger-preview`.

Публикация создаёт неизменяемый ZIP с именем SHA-256, подписывает архив и JSON-манифест. Локальный Go-мост проверяет подпись манифеста, поля совместимости, размер, обычный тип файлов и хеш архива. Его HTTP-адрес слушает только loopback и требует отдельный случайный Bearer-токен окна; разрешён только GET. Доступ к очереди или произвольным файлам через канал не добавляется. Sparkle дополнительно проверяет EdDSA архива **до распаковки**. Ссылки на пакеты ограничены тем же локальным адресом.

Поток XML создаётся локально из уже проверенного подписанного манифеста. Сам этот динамический XML не подписан отдельной подписью Sparkle и не используется как удалённый HTTPS-feed. При добавлении удалённой доставки этот контракт потребуется пересмотреть; токены приложения нельзя передавать произвольным адресам или встраивать в сборки.

Ad-hoc подпись Mac-приложения и EdDSA подпись обновления решают разные задачи. Последняя проверяет происхождение пакета, но не заменяет Developer ID и notarization для распространения на чужих Mac. Автоматический откат после неудачного первого запуска новой версии ещё не принят.

## Публикация разработчиком

Команды выполняются из корня исходников; Python и инструменты подписи нужны только разработчику, не пользователю приложения.

```sh
# Один раз создаётся ключ в Keychain; существующий не заменяется.
/path/to/sparkle/bin/generate_keys --account agent-messenger-preview

# Публичный ключ должен совпадать с ключом в репозитории.
SPARKLE_DIR=/absolute/path/to/sparkle \
  bash scripts/build-mac-app.sh /absolute/path/to/output 0.0.0-preview.NUMBER FULL_SOURCE_SHA

python3 scripts/publish-local-update.py /absolute/path/to/output \
  --sparkle /absolute/path/to/sparkle --notes /absolute/path/to/notes.txt
```

Каждому пакету нужен новый целочисленный номер. Более старая или конфликтующая сборка с тем же номером не публикуется. Публикатор сверяет ZIP с `.app`, проверяет подпись bundle, версию, совместимость и ключ, затем подписывает. `--directory` задаёт отдельный канал для тестов. Основной канал находится в пользовательском `Library/Application Support/AgentMessenger/updates`. Его содержимое и приватный ключ не добавляются в Git.

## Проверки и оставшиеся этапы

На Mac выполнен настоящий переход preview.5 → preview.6 через значок и кнопку установки: приложение открылось вновь, очередь и попытки побайтно эквивалентны прежнему снимку, прежний клиент остался запущен. Реальных моделей в проверке нет. Это проверка локального пути, не удалённой доставки.

Go-тесты проверяют подпись и повреждение манифеста, несовместимый API/архитектуру, размер, подмену пути, symlink, повреждение ZIP и сохранность старой копии клиента при замене приложения. Проверка оболочки подтверждает отсутствие новых попыток и дубликата клиента после закрытия окна.

До полного этапа обновлений остаются: авторизованный канал закрытых GitHub Releases, обновление самого фонового клиента, резервное копирование/откат с проверкой первого запуска, чистая установка с Gatekeeper на другом Mac и runtime-приёмка остальных платформ. Эти пункты не считаются пройденными наличием кнопки.
