# План до первого релиза

Обновлено 6 ноября 2026 года. Это актуальная последовательность работ поверх исходного [MVP](MVP.md), [архитектуры](PLAN.md), требований [окна](APP.md) и [размещения брокера](DEPLOYMENT.md). Дата релиза не назначена: переходы определяются проверками, а не процентом написанного кода.

## Текущее положение

Текущий функциональный шаг preview.19 принят на Mac: [создание и явный запуск отдельной тестовой сессии Claude из окна](SCOPED_LAUNCH.md). После имитатора проверен настоящий Claude Code 2.1.318: два последовательных письма, два подтверждённых ответа в одном процессе, автоматическое появление ответов и сохранение трёх старых писем других сессий. Оболочка обновлена через нативный обновлятор до preview.19. Автоматическая смена версии работающего фонового клиента по-прежнему отдельная задача. Следующий шаг — постоянный Codex, затем несколько независимых владельцев без голодания и Claude ↔ Codex на одном Mac. Косметические замечания включаются в функциональные шаги, не образуют отдельную очередь выпусков.

Мы на этапе локального технического прототипа на Mac. Есть Go-клиент, SQLite, защищённое владение сессиями, связанные ответы MCP, постоянный Claude, точный resume, явное восстановление после настоящей перезагрузки и фоновый запуск. Это проверено отдельными тестовыми CLI-разговорами, не рабочими чатами. Продукт размещён в `cmd/messenger` и `internal`; ранние эксперименты остаются отдельно. Технический preview и полный релиз для трёх ОС — разные контрольные точки.

В постоянном продуктовом режиме проверен Claude на Mac. Более ранние опыты Codex/Cursor не заменяют их приёмку в текущем клиенте. Сборки Linux/Windows не заменяют запуск на этих ОС. Добавлен локальный браузерный интерфейс с историей, отправкой и управлением очередью. Исходящие после первой записи клиентом переживают закрытие вкладки и перезапуск UI. Есть сборщик нативного Mac preview и установка в пользовательский каталог, проверенная локально; добавлена первая [нативная оболочка Mac](MAC_APP.md). Подписанное распространение, приёмка оболочки на других Mac и сетевой брокер ещё не завершены.

Открытая проблема: полное завершение CLI и безопасное освобождение его сессии в той же загрузке Mac. Фоновый `start` позволяет закрыть терминал, сохранив живого владельца, но не решает эту проблему. Освобождение по таймеру, пустой группе или одному завершённому PID не добавляется.

Preview.19 опубликован после четырёх успешных заданий CI. Фоновый клиент обновлён отдельно с неизменными прежними данными; оболочка установлена через обновлятор. После двух реальных ответов тестовая очередь поставлена на паузу, живой владелец сохранён. [Отчёт выпуска](reports/2026-11-06-window-launch-mac.md). Продолжается [исследование адаптера Codex](CODEX_ADAPTER_NEXT.md): соединение app-server подтверждено без модели; пустой новый разговор после выхода ещё не гарантирует сохранённый rollout. Воспроизводимая проверка установила, что пустая таблица MCP не очищает унаследованные серверы.

## Принятый путь доставки обновлений

Доставка новых сборок через окно принята на Mac до preview.17 включительно. Следующие пункты описывают контракт обновления; автоматическая смена фонового клиента ещё не принята. Текущая работа — настройка сессий и локальный обмен с сохранением ограничений владения процессами.

1. Интегрировать Sparkle в оболочку Mac: проверка версии, ненавязчивый значок, ручная проверка, описание изменений и установка по кнопке. Базовый механизм — [Sparkle](https://sparkle-project.org/documentation/), не собственная замена исполняемых файлов.
2. Подготовить подписанные обновления и канал доставки. Репозиторий открыт с разрешения владельца после проверки истории. Публичные пакеты загружаются без аккаунтного ключа; подписи проверяются приложением.
3. Проверить совместимость и условия перезапуска фонового клиента. Обновление только окна не выдавать за обновление всего продукта. Нельзя удалять защитные резервы, убивать CLI или считать паузу доказательством безопасной остановки.
4. Выпустить две последовательные тестовые сборки и пройти путь от значка до перезапуска, затем проверить сохранность очереди и отказ при сбоях. После этого следующие законченные шаги разработки доставляются тем же способом.

Статус: локальный подписанный канал реализован и проверен переходом preview.5 → preview.6 из окна. Работает обновление приложения с сохранением прежнего фонового клиента. Репозиторий открыт по разрешению владельца после проверки истории на секреты. Доставка подписанных пакетов из публичного GitHub реализована без аккаунтного ключа в приложении; переход preview.12 → preview.13 через GitHub [проверен на Mac](reports/2026-11-06-github-update-mac.md). Смена версии фонового клиента и полный откат ещё не приняты. Первая сборка с обновлятором установлена однократно вручную; следующие локальные сборки устанавливаются через окно. См. [границы и проверки](UPDATES.md).

## Что может потребовать участия владельца

Вход в аккаунты через штатный браузер; реальные Windows/Linux-компьютеры для приёмки; выбранный VPS для удалённого испытания; доступ к подписи/распространению сборок, если выбранный способ выпуска этого потребует. До этих точек реализация, локальные проверки и документация продолжаются без согласования каждого технического шага. Самостоятельно перезагружать компьютер, менять публичность репозитория или брать рабочие GUI-чаты нельзя.

## Условия, которые не меняются

- Messenger передаёт сообщения и не управляет файлами или задачами проекта.
- VPS необязателен. Один серверный компонент работает на выбранном компьютере либо VPS; автоматического выбора запасного брокера нет.
- Ожидание, показ статусов и технические ACK выполняются обычным кодом. Новые содержательные письма могут тратить токены; одно письмо не равно одному API-вызову.
- Для координатора нужны пределы автоматических ответов, остановка циклов и возможность собирать несколько уведомлений в одно обращение. Экономия проверяется наблюдениями, не обещается процентом.
- Неизвестный результат не превращается в успех или автоматический повтор. ID сессий, аккаунты, ключи и очереди не публикуются.
- Cursor GUI и рабочие разговоры не захватываются. Смена координатора переносит роль и сообщения, а не внутреннюю историю между моделями.

Подробный контракт — [обновления Mac-приложения](UPDATES.md): доверенные подписи, совместимость UI/клиента/схемы, прерываемая загрузка, сохранение данных и отложенная установка при активном владельце CLI. Проверка не расходует токены модели. Автоматическая смена фонового клиента и полный откат ещё не приняты.

## Порядок следующих обновлений

По просьбе владельца от 6 ноября: замечания интерфейса накапливаются вместе с текущим этапом разработки. Один законченный шаг и накопленные правки выходят одним обновлением; отдельный пакет на каждую мелочь не готовится. Сначала завершаем проверку этапа, затем публикуем подписанную сборку в канал и сообщаем о доступности.

## Публикация для трёх платформ

Общий релиз включает macOS, Windows и Linux. На главной странице каждой платформе отведён отдельный пункт скачивания. До реальной приёмки он обозначен «готовится». Для каждой ОС нужны собственные окно/пакет, канал подписанных обновлений, проверка чистой установки и сохранения очереди. Кросс-компиляция Go не заменяет эти проверки. Нативная Mac-оболочка не ограничивает архитектуру Messenger этой системой.

При каждом завершённом шаге исходники и актуальные README/инструкции переходят в основную ветку вместе с публикацией пакета. Накопленные замечания интерфейса входят в тот же выпуск.

Очередь сообщений отображается справа от переписки по умолчанию; значок вверху скрывает и возвращает панель. Отдельной вкладки очереди нет. Сейчас панель показывает количество ожидающих писем и требующие внимания сессии по данным клиента. У панели очереди, истории сообщений и списка компьютеров отдельная прокрутка; тема, текущая версия и обновление закреплены внизу слева.
