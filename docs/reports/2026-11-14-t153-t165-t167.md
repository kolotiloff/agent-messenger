# T-153 and T-165–T-167: setup, sign-in and LAN discovery

Date: 2026-11-14. Branch: `codex/t163-theme-switch`. Owner authorized a combined release with T-163/T-164. Not released yet.

## Changes

- T-153: install Claude Code, Codex or Cursor using its official standalone installer in a visible terminal. Download before execution so a failed download is not mistaken for a successful empty shell pipeline. Find an already installed CLI through the terminal's PATH; skip installation if one is found. Atomic private receipts survive window restarts. Validate paths and Windows shims, preserve an existing profile, register once and check version/sign-in. An absent receipt or uncertain registration is not retried. Manual file selection remains available.
- T-165: Trust opens the registered CLI in the selected project folder, after showing that folder and the meaning of trust. The owner confirms through the CLI; a graphical agent application is unnecessary. No trust files or sandbox settings are modified by Messenger.
- T-166: launch an independent interactive Windows console through PowerShell Start-Process. Await short terminal launchers and report their errors/unconfirmed outcome; Linux loads the owner's login-shell PATH. The frontend also now displays non-409 structured failures and their copyable manual command instead of discarding them. Errors were also rendered inside the hidden Tasks tab when an agent action failed. Non-task errors now appear above the visible screen. A browser fixture explicitly rejects login and asserts that the error and manual command are visible on Agents. The exact sign-in failure on the acquaintance's computer was not reproduced.
- T-167: resend only public UDP discovery questions during the bounded search, and report a server's unavailable UDP listener instead of displaying an unusable short invitation. No-host guidance names Windows firewall UDP 47100 and network isolation; long-code connection remains available. No automatic registration/code-proof retry or firewall change. The owner's two-computer failure was on Windows; its exact cause is unconfirmed.
