# T-170 first login with a missing standard profile

Date: 2026-11-14. Branch: `codex/t170-first-login`. Included in owner-requested 0.72 with T-168/T-169.

## Reproduced blocker

The owner clarified Cursor authorization concerns Windows and recalled text about checking entered data. The precise message/screenshot is unavailable. `discovery` provides the standard profile path even on a fresh computer. The agent card falls back to that path and posts it to `agent-login`. `agentCommand` previously required `CanonicalEnvironment` to succeed, so a missing profile rejected the request before opening any terminal. `serveAgentLogin` returned plain HTTP 400, which the UI reduced to «Проверьте введённые данные».

Allow a missing standard profile only. The CLI creates its own storage when it signs in. Do not create a directory, read credentials, or silently replace an explicit custom profile. A missing custom directory, a file in place of a directory or a missing executable stays refused. Login/logout errors now return JSON details naming the unavailable path and the settings action.

This reproduces a plausible cause of the reported message; it does not establish the exact cause on the acquaintance's computer or prove their account can sign in.
