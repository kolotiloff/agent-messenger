# Первые компоненты постоянного Codex на Mac

6 ноября 2026. macOS arm64, установленный Codex CLI 0.155.1, Go 1.27.3.

## Проверка настоящего app-server без модели

```sh
MESSENGER_CODEX_PROBE=/absolute/path/to/codex \
  go test -race -count=1 -ldflags=-linkmode=external ./internal/adapters
```

Переменная включает только дополнительную проверку установленного CLI. Обычный `go test` её пропускает. В каждом случае создаются отдельные временные HOME/CODEX_HOME и рабочая папка, окружение задаётся явным списком, credentials не копируются. Хранилище авторизации установлено в `file` внутри пустого профиля. Запускается отдельный stdio-процесс, не демон пользователя.

Отправляются только `initialize`, уведомление `initialized` и `config/read`. В тестовом транспорте нет разрешения на `thread/start` или `turn/start`; запрещённый метод отклоняется до записи. Три проверки прошли:

| Профиль | Результат Go-проверки |
|---|---|
| Пустой управляемый профиль | Принят |
| Искусственный MCP в файле + пустая таблица MCP во флагах | Отклонён: сервер остался включён |
| Тот же MCP с явным `enabled=false` | Принят |

Во всех трёх случаях app-server штатно завершился после закрытия stdin. Модельных ходов нет. Рабочие профили и GUI-сессии не использовались.

## Автоматические проверки Go

- Неполные настройки, `null` вместо отключения, неявно включённый MCP, включённые hooks/goals, разрешение записи и web search отклоняются.
- Ошибочный/пустой RPC ID, запрос сервера вместо ответа, одновременные result/error, повреждённый JSON и EOF не приводят к повтору запроса. Содержимое ошибки сервера не попадает в сообщение тестового транспорта.
- Проверены связанные чтение и запись ответа с точными thread/turn ID. Вызывающая сторона обязана привязать обработчики к конкретной попытке в базе.
- Чужой разговор/ход, старая квитанция, выбранный моделью адресат, повторный call ID и посторонний инструмент не вызывают запись ответа. После отказа следующий корректный вызов также не открывает инструменты заново.
- Ответ записывается до успешного возврата инструмента. Ошибка записи оставляет результат неопределённым; завершение хода не маскирует её.
- `completed` без связанного ответа, `failed`, `interrupted`, чужое завершение, вызов после `Stop` и повторное завершение отклоняются.

Полный `scripts/check.sh` на Mac прошёл на Go 1.27.3 и Go 1.22.2: форматирование, зависимости, vet, все race-тесты. После ужесточения тестового RPC-декодера повторно прошли пакет адаптеров с настоящими немодельными проверками установленного Codex и полный набор на Go 1.22.2.

## Границы приёмки

Это подготовительные компоненты, ещё не запуск Codex из продукта. Реальные model turns, выдача и сохранение ID новой сессии, resume, постоянный транспорт, обработка событий до RPC-ответа, привязка к SQLite и глобальным резервам, защита от изменения конфигурации после проверки и существующая авторизация в управляемом профиле остаются следующими шагами. Текущий Claude и его очередь не изменялись. Новой пользовательской сборки из этой промежуточной работы не выпускали.
