# T-168 setup recovery and T-169 Cursor sidebar

Date: 2026-11-14. Branch: `codex/t168-setup-recovery`. Not released.

## Findings and changes

The owner confirmed the installation report concerns Codex on another Mac. The terminal was closed after an installation prompt; the exact prompt and process exit are unavailable. In 0.71, a setup ID without a result was labelled running forever. The UI acknowledged uncertainty but offered no recovery action in the row. A separate Find already existed in settings.

Missing results now mean unknown, and the install row offers Find. A successful explicit find/registration marks the old attempt's display recovered, preserving its files and unknown installer exit across restarts. Late results cannot register it again, and neither an unknown install nor an uncertain registration is retried. POSIX EXIT/HUP/INT/TERM handlers write interrupted when no final receipt exists. An uncatchable exit or an old receipt still uses the unknown/recovery path. If Find itself is closed, manual file selection remains available; Messenger does not claim success.

The sidebar's coordinator-name classifier knew Claude/Codex but not Cursor. A Cursor client name was therefore displayed as an extra raw-name row alongside a registered Cursor worker. Cursor names now merge with that row for both local and remote computers. Unknown clients retain their name with a tooltip explaining that it is a Messenger chat. Coordinator connection metadata is not live worker execution evidence (D-064/D-069).
