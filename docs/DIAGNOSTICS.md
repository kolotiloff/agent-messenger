# Диагностика без запуска CLI

```sh
messenger --root /absolute/data/path doctor
messenger --root /absolute/data/path doctor --json
```

Команда работает и при остановленном клиенте. Она ищет кандидаты исполняемых файлов в `PATH`, проверяет наличие каталога данных и запрашивает только `status` у существующего локального клиента. Не создаёт каталог/базу, не устанавливает программы, не запускает CLI, не читает учётные данные и не меняет блокировки. Ожидание ответа управляющего сокета ограничено 750 мс; недоступность не считается доказательством остановки процессов.

Это первая часть диагностики для будущего окна. Проверки версии, подлинности найденного CLI, штатного входа и конкретной привязки сессии пока не реализованы и явно возвращают `not_checked`. Наличие исполняемого файла не означает «агент готов». Отсутствие в `PATH` не доказывает отсутствие программы на всём компьютере; GUI-приложение может иметь другой `PATH`.

Имена поиска: `claude`, `codex`, для Cursor сначала `cursor-agent`, затем `agent`. Последнее имя может принадлежать другой программе: пока версия/идентичность не проверены, это только кандидат. Произвольные найденные программы не исполняются ради диагностики. Относительный путь, отклонённый Go как `ErrDot`, не принимается за найденный CLI.

## Машинный формат, версия 1

`doctor --json` выдаёт один объект:

- `schema_version`, `checked_at` (UTC), `os`, `arch`;
- `data.root` и `data.state`: `exists`, `missing`, `not_directory`, `unreadable` — только сведения о каталоге, не результат проверки базы;
- `controller.state`: `reachable`, `unreachable` или `unknown`; при подтверждённом статусе — PID клиента, пауза, разрешение CLI, число ожидающих писем/занятых сессий и существующий статус брокера;
- `agents`: три независимые карточки, `cli.state`, путь кандидата, имя команды, источник `PATH`, `identity`, `version`, `authentication`, `session`;
- `probe_cli_starts=0`: сама диагностическая операция не запускала CLI. Это не счётчик действий другого уже работающего клиента.

Текст переписки, ID разговоров, токены MCP, содержимое профилей, сырые ошибки и расширенное поле `status.detail` в отчёт не включаются. Пути и PID — локальная диагностика: перед публикацией их следует обезличить.

`held_sessions` включает любого удерживаемого владельца, в том числе здоровый постоянный процесс; это не число ошибок. Статус брокера `not_configured` не означает сетевое подключение. Индивидуальная готовность сессий из общих счётчиков не выводится.

Код завершения 0 означает «отчёт сформирован», даже если CLI не найден или клиент не ответил. Для автоматизации нужно читать поля JSON. Неизвестные флаги отклоняются; у команды нет разрешения запускать модели.

## Следующие части

Ограниченные по времени штатные проверки версии и входа, явный путь CLI вне `PATH`, статусы конкретных привязок и действия установки/авторизации. Эти функции должны быть отдельными проверяемыми операциями с актуальной документацией провайдеров. Ошибка входа не должна стирать профиль или предлагать повторную авторизацию без необходимости.
