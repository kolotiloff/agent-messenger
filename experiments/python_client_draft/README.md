# Черновик Python-клиента

Этот каталог сохранён, а не подключён к продукту. Его начали как постоянный клиент на Python; до тестов и коммита решение изменилось: постоянный клиент и будущий брокер пишутся на Go. Планового доделывания этого черновика нет. Продуктовая команда — `cmd/messenger`.

Черновик не входит в `go test` и не является приёмкой этапа. После переноса в этот каталог его собственные тесты один раз запущены здесь:

```sh
python3 -m unittest discover -s experiments/python_client_draft/tests -q
```

Повторный запуск в этой Linux-среде: 31 тест, все прошли. Это проверка сохранённого черновика, не приёмка продукта и не замена отчётов Mac. Продуктовые проверки — тесты Go-клиента.

Что в нём полезно как чтение сценария, рядом с уже проверенным стендом `experiments/session_safety`:

- `agent_messenger/behavior.py` — формулировки паузы, остановки задания, завершения клиента и список ограничений.
- `agent_messenger/identity.py` — канонический каталог окружения и ключ сессии, а не произвольное имя профиля.
- `agent_messenger/store.py` — очереди, псевдонимы, дедупликация ответа и отказ снимать блокировку без доказательства.
- `agent_messenger/adapters.py` — явный resume и проверка событий Claude, Codex и Cursor.
- `agent_messenger/process_info.py` — снимок процесса не объявляется доказательством выхода всех потомков.

Расхождение, которое в Go не перенесено: черновик при следующем старте сам переводит чужую активную попытку в `uncertain` и отзывает её MCP. В Go-клиенте `shutdown` этого не делает. Пока оператор не вызовет `stop-job`, уже запущенный CLI может дописать ответ, а новая попытка этой сессии всё равно не начинается.
